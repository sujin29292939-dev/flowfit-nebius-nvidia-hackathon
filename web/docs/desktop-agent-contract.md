# FlowFit Desktop Agent Contract

FlowFit의 본체는 사용자가 데이터를 입력하는 웹 폼이 아니라, 새 알림을 감지하고 로컬 컴퓨터를 확인·조작하는 AI 작업자다.

## Product Promise

연결된 프로그램에 새 알림이 들어오면 알림 감지 프로그램이 먼저 감지한다.

알림 감지 프로그램은 어느 앱에서 알림이 왔는지만 FlowFit에 전달한다.

누가 보냈는지, 어느 대화방인지, 어떤 내용인지, 무엇을 해야 하는지는 FlowFit이 직접 앱을 열어 확인한다.

AI 작업자는 컴퓨터 화면을 확인하고, 필요한 프로그램을 조작하고, 처리 준비를 마친다.

담당자나 사장은 최종안의 수락, 수정 요청, 담당자 이관만 결정한다.

## Main Flow

1. 새 알림 감지
2. 알림이 발생한 앱 식별
3. FlowFit이 해당 앱 열기
4. FlowFit이 발신자, 대화방, 내용을 직접 확인
5. 화면 캡처와 필요한 프로그램 확인
6. 정보 추출
7. 답장 또는 처리안 작성
8. 담당자 수락 요청
9. 수락 후 전송 또는 처리 기록 저장

## User-Facing Rules

사용자에게 API 키, 서버 주소, 웹훅, 모델명, 프롬프트 설정을 요구하지 않는다.

사용자에게 원문을 매번 복사해서 붙여넣게 하지 않는다.

사용자에게 먼저 요청을 입력하게 하지 않는다.

사용자에게 여러 설정 화면을 먼저 보여주지 않는다.

사용자에게 보이는 기본 화면은 감지된 알림, 준비된 처리안, 수락 버튼이어야 한다.

알림 감지 프로그램이 사용자 메시지 내용이나 발신자를 판단하게 하지 않는다.

## Agent Tool Boundary

AI 작업자는 다음 도구를 가진다.

- 화면 캡처
- 알림 발생 앱 확인
- 창 찾기
- 텍스트 읽기
- 클릭
- 입력
- 복사
- 붙여넣기
- 브라우저 조작
- 파일 확인
- 처리 기록 저장

## Safety Rules

AI는 사람 수락 없이 외부 메시지를 최종 전송하지 않는다.

AI는 확인하지 않은 재고, 단가, 출고 시간, 책임 판단을 확정 표현으로 쓰지 않는다.

알림 감지 프로그램은 메시지 내용, 발신자, 고객 정보, 처리 의도를 추정하지 않는다.

발신자와 내용 확인은 FlowFit이 해당 앱을 직접 열어 수행한다.

AI는 화면 캡처와 조작 기록을 작업 단위로 남긴다.

AI는 담당자 수락 전에는 준비된 처리안과 판단 근거만 띄운다.

## Implementation Boundary

Collector 업스트림 전송은 3001 엔진 하나만 사용한다.

3007 앱은 감지기의 push 수신 대상이 아니다.

3007 앱은 엔진 상태 또는 로컬 감지기 상태를 pull 해서 조회하는 화면이다.

Next 앱은 수락 화면과 처리 기록 조회를 담당한다.

알림 감지 프로그램은 새 알림 발생 앱만 전달한다.

로컬 데스크톱 작업자는 앱 열기, 화면 캡처, 컴퓨터 조작, 내용 확인을 담당한다.

두 구성요소는 로컬 저장소나 localhost API로만 연결한다.

배포 제품에서는 일반 사용자가 AI API를 직접 입력하지 않는다.
